# rank_forward — unidirectional ranking-heuristic baseline (PyTorch)

A from-the-paper reimplementation of

> Chrestien, Edelkamp, Komenda, Pevný. *Optimize Planning Heuristics to Rank,
> not to Estimate Cost-to-Goal.* NeurIPS 2023. https://arxiv.org/abs/2310.19463
> (reference code: https://github.com/aicenter/Optimize-Planning-Heuristics-to-Rank)

It is a **forward (unidirectional) A\*/GBFS** planner whose heuristic `h(s,θ)`
is trained by a **ranking** loss instead of regression to cost-to-goal. It
exists as a baseline to compare against our bidirectional front-to-front
method, on the **same** Sokoban instances and the **same** node-expansion
metric.

## Idea

A heuristic is *strictly optimally efficient* (expands only states on one
optimal path) iff it is a **perfect ranking**: for every on-path state `s_i`,
every off-path state `s_j` still in the open list has strictly higher merit
`f = α·g + β·h`. The losses minimise rank violations:

- **L\*** (A\*: α=β=1, rank on `f=g+h`) and **L_gbfs** (GBFS: α=0,β=1, rank on `h`):
  `Σ_{s_i∈path} Σ_{s_j∈negatives} softplus(α(g_i−g_j)+β(h_i−h_j))`.
  Negatives = distance-1 off-path siblings of the path; following Definition 1
  literally, a sibling of `s_p` is contrasted with **every** later path state
  `s_i, i≥p+1` (it lingers in the open list). `LOCAL_PAIRS=1` uses only the
  same-depth competitor.
- **L_rt** (Eq. 6, on-path consecutive), **L2** (regress `h→h*`), **L_be**
  (Bellman, ref [49]) — baselines.

## Files

| file | role |
|---|---|
| `forward_search.py` | `ForwardSearch`: A\*/GBFS, duplicate detection, reopening (A\* only, per paper), expansion counting matching our bidirectional `iteration`, budget |
| `ranking_net.py` | `build_forward_model`: default `SmallCNN` (reused), optional `coat` (the paper's attention net) |
| `trajectory.py` | solve an instance **optimally** (admissible-A\*), replay to collect path + distance-1 off-path negatives |
| `losses.py` | `lstar / lgbfs / lrt / l2 / bellman` (vectorized) |
| `dataset.py` | load `solvable10_3box.txt`, deterministic train/eval split, cache solved instances |
| `trainer.py` | one-instance-per-step loop, one persistent Adam |
| `forward_run.py` | build → train → eval → report (node-expansion metrics + speedup) |
| `config.py` | env-overridable knobs |

## Run

```bash
# from repo root
PYTHONPATH=. python rank_forward/forward_run.py
# example overrides:
LOSS=lgbfs ALG=gbfs N_TOTAL=2000 STEPS=40000 PYTHONPATH=. python rank_forward/forward_run.py
```

Key knobs (see `config.py`): `N_TOTAL`, `N_EVAL`, `MODEL` (`smallcnn`|`coat`),
`LOSS` (`lstar`|`lgbfs`|`lrt`|`l2`|`bellman`), `ALG` (`astar`|`gbfs`),
`STEPS`, `LR`, `MAX_ITERS`, `USE_DEADLOCK`, `REDUCTION`, `LOCAL_PAIRS`.

## Comparison protocol

- **Same instances**: `game.getData.get_solvable_data(limit=N_TOTAL)`, split into
  a train prefix and a disjoint eval suffix (`N_EVAL`, default 200 — the paper's
  test-set size).
- **Same metric**: *productive node expansions* (one pop→close→expand), the unit
  our bidirectional `BidirectionalF2FSearch.iteration` counts. Per puzzle we
  report `first_solved_iter` (the forward analogue of `first_meeting_iter`).
- **Same budget**: `MAX_ITERS` (default 10000), as in `learning/online_run.py`.
- **Same encoder** (default): `SmallCNN`, so the comparison isolates *loss +
  search direction*, not network capacity.
- Report: solved %, mean/median expanded nodes, and speedup vs the blind
  (h=0) forward A\* baseline. To compare against the bidirectional method, run
  `learning/online_run.py` on the same dataset (it already reports the same
  units) and put the tables side by side.

## Deliberate departures (documented)

- **Counting** — we count productive *expansions* (not heap *pushes* as the
  reference TF code does), to match our bidirectional metric. So our absolute
  expanded-node numbers are not directly comparable to the paper's tables; the
  valid axes are (a) ranking-vs-regression ordering and (b) forward-vs-bidirectional.
- **Architecture** — default `SmallCNN` (23.6k params), not the paper's larger
  CoAT net (`MODEL=coat` for a faithful, heavier ablation).
- **Optimal labels** — generated by our own admissible-A\* solver (the paper used
  SymBA\*). The admissible MWPM-Manhattan heuristic is used **only** for label
  generation, never in the compared search.
- **Deadlock pruning** — OFF by default (domain-agnostic, per `CLAUDE.md`).
  `USE_DEADLOCK=1` matches the bidirectional forward side's pruning.
- **Reduction** — `sum` (paper) by default; `REDUCTION=mean` available.
- **L_gbfs** — paper-symmetric with L\* (no `g`-equality gate that the reference
  code applies).

## Reference-code bugs avoided

The original research code rebuilt the Adam optimizer every minibatch (killing
momentum) and trained a different network than the one its data-generation
search used. We use one persistent optimizer and train the single network that
is then searched with.
